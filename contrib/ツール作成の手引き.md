# 評価ツール 作成の手引き

> 2026-09-10 時点の決まりごとをまとめたものです。
> ここに沿って作っていただくと、そのまま公開サイトへ組み込めます。
> 迷ったところは決めずに置いておいて構いません。管理者側で調整します。

---

## 0. このツール群がしたいこと

評価尺度を実施したときの**採点を自動化し、QRコードでカルテへ転記する**ためのものです。
病棟で iPad・iPhone を持ったまま使うため、次の2つを何よりも優先します。

- **電波が無くても動く**こと
- **入力が消えない**こと

---

## 1. かならず守ること（技術）

| 項目 | 決まり |
|---|---|
| ファイル構成 | **HTMLファイル1つ**（CSS・JavaScriptも中に書く） |
| 外部の読み込み | **なし**。CDN・外部フォント・外部ライブラリは使わない |
| フォント | 埋め込まない。`font-family` に `"Hiragino Sans","Yu Gothic","Meiryo",sans-serif` を指定する |
| QRコード | ライブラリのJSをファイル内に直接書く。**UTF-8変換は `TextEncoder` を使う** |
| データ保存 | `localStorage` の**下書きだけ**。`sessionStorage`・Cookie・外部送信は使わない |
| 動作環境 | Safari / Chrome の最新版（iPad・iPhone・PC） |
| 画面の拡大 | `<meta name="viewport" content="width=device-width, initial-scale=1.0, user-scalable=yes">` |

> **QRコードの `TextEncoder` について**
> よくある簡易版ライブラリは、日本語を含むとQRの先頭に見えないゴミが付き、環境依存の漢字が化けます。
> ライブラリ内の `QR8bitByte` を次の1行に置き換えるだけで直ります。
> ```js
> this.parsedData = Array.prototype.slice.call(new TextEncoder().encode(data));
> ```

## 2. 画面の作り

### 2-1. 基本

- 回答の順序は自由。どの項目からでも入力できるようにする
- **選択済みの選択肢をもう一度押したら、未回答に戻す。**手袋のまま片手で操作するので誤タップは必ず起きます。取り消せないと「実施していない項目」に点数が入ったまま確定してしまいます
  - 取り消したときは「未回答に戻しました」と画面に一瞬出す（無言で消えると壊れたと誤解されます）
- タブがある場合は、タブ帯を画面上部に固定する（`position:sticky`）。折り返さず横1列にして、入りきらない分は横スクロールにする
- ボタンは指で押せる大きさにする。秒数を測るボタンは **96×48px 以上**

### 2-2. 画面に出す注意書きは最小限にする

注意書きを足し続けると、**どれも読まれなくなります。**常時出してよいのは次の3つだけです。

| 種類 | 例 |
|---|---|
| ① 点数が変わるもの | 「未回答は0点として計算していません」／「空欄にすると満点として扱う」 |
| ② 入力が消えるもの | 下書きの確認バナー／保存が止まっている警告帯 |
| ③ 読み取り漏れにつながるもの | QRの未回答件数／QRを何枚に分けたか／QR生成後の手順 |

- **同じ内容を2か所に書かない**（書く場所は「その操作をする直前」の1か所）
- 1つの注意書きは**2行以内**。超えるなら内容を減らすか、文言ではなく**ボタン名**で伝える
- 個人情報の説明は「**※ 氏名はQRコードに入りません。**」の1行に集約する

---

## 3. 患者情報

- 入力欄は**氏名のみ**（評価日の欄は置きません。カルテ側に記録日が入るため）
- 氏名は**QRコードに含めない**
- 氏名の下の注記は「※ 氏名はQRコードに入りません。」の1行だけ

---

## 4. 採点の表示

- 回答が1つも無いときは「—」
- 回答が1つ以上あるときは、**その時点までの小計**をリアルタイムに出す
- **未回答は0点として扱わない。**「未回答 n件（0点として計算していません）」を必ず併記する
- **判定ラベル（正常・軽度など）は、全項目に回答したときだけ出す**（未回答があると過小評価になるため）
- スコア表示は、その尺度の**全項目より下（末尾）**に置く
- **「入力しないこと」が特定の点数として扱われる採点ルールがあるときは、画面に赤字で常時書く**
  - 例：「押していない項目は未評価であり、0点ではありません」
  - この種のルールは、詳細仕様書にしか書かないと現場では読まれません

### 秒数を測る項目がある場合

- 入力欄の隣に［計測］ボタンを置く（96×48px以上）
- 計測中は赤地で「■ 停止 3.2秒」、記録後は「▶ 測り直す」
- **同時に動かせるのは1つだけ。**別の項目で始めたら、動いていた方は自動で止めて記録する
- 数値の入力欄には `inputmode="decimal"` を付ける（iPadでフルキーボードが出ないように）

## 5. QRコード

### 5-1. 中身

- **氏名は入れない**
- **1行に1項目**（カルテの入力欄は横幅が狭いため、詰め込むと折り返して読めなくなります）
- 未回答が1件以上あるときは、
  - 合計の行に `(途中経過)` を付ける
  - 末尾に `※未回答 n件（0点として計算していません。途中経過です）` を足す
- **1件も実施していない部分は、見出しごと出さない。**空欄が並ぶと、読む人が「実施したが測れなかった」のか「やっていない」のか判断できません
  - どこも実施していない場合は `（未実施）` とだけ出す

### 5-2. 大きさ

QRが読めなければツールの意味が無くなります。次の2つは必ず守ってください。

- **画面幅を超えないようにする**：`canvas{max-width:100%;height:auto;image-rendering:pixelated}`
  （指定が無いと右端の位置検出パターンが画面外に出て読めなくなります）
- **1枚あたり120文字を目安に、超えたら複数枚に分ける**
  - 1行目（検査名）は各枚に付け直し、見出しに `（1/3）`、QRの上に `1 / 3 枚目` を出す
  - 画面に「QRコードを n枚 に分けています。1枚目から順に読み取ってください」と出す

### 5-3. QRを出したあと

QRが出たところで手が止まる、という声が複数あったため、QRの直前に手順を常時表示します。

```
このあとの手順
① カルテ端末のカメラで下のQRコードを読み取る（複数枚なら「n枚すべて」と出す）
② カルテに貼り付いた内容を目で確かめる
③ 確認できたら［この端末から入力を消す］を押す
　（入力はこの端末に一時保存されています）
```

QRの下には、QRに入っているテキストをそのまま表示し、［テキストをコピー］も置きます。

## 6. 下書きの自動保存

入力途中でアプリが落ちたり、共用端末で前の患者の入力が残ったりする事故を防ぐ仕組みです。

- `localStorage` に**3つの保存枠**（A・B・C）を用意する
  - 枠の数を変えるだけで済む書き方にする（「Aが空ならA、Bが空ならB」と分岐を書かない）
- 保存するもの：氏名・回答一式・最終更新日時
- 保存のタイミング：入力のたび（400ms程度まとめてよい）
- **起動時に自動で復元しない。**確認バナーを出して、検査者に選んでもらう
  - バナーの先頭に件数と空き状況を出す
  - 1件ごとに「n件目：氏名・回答件数・最終更新」＋［この続きをする］［これを消す］
  - 空きがあるときは［残したまま新しく始める］も出す
- **QRを作っただけでは消さない**（転記できなかったときにデータが消えてしまうため）

### 必ず守ってほしい3点

**(a) 消したあとは、そのページで保存を再開しない**
［この端末から入力を消す］のあとに画面を操作すると、同じ枠へ書き戻されて前の患者の入力が残ります。
消したら保存先を `null` にして、以後保存しないでください。［この患者を終わる］で再開します。

**(b) 保存されていないことを画面に出す**
枠が全部埋まっていて確認バナーを選んでいない間は、保存が止まっています。バナーは上部にあるので
スクロールすると見えません。**画面下部に固定した赤い警告帯**を出してください。

**(c) 「下書きに中身があるか」の判定は、保存している全キーを見る**
氏名だけで判定すると、氏名未入力のまま検査を進めた下書きが「空き」と見なされ、上書きで消えます。

## 7. 「消す」ボタンの呼び方

現場から「消すための言葉が8種類あって、どれが何を消すのか分からない」という指摘がありました。
**下の呼び方に統一し、これ以外の言い方をしません。**

| 消える範囲 | ボタンの文言 | 置き場所 |
|---|---|---|
| この患者の入力すべて（全項目・氏名・下書き） | **この患者を終わる** | ヘッダー右上 |
| その検査の回答とQRだけ（氏名・他の検査は残る） | **この検査だけやり直す** | 各検査の操作ボタン列 |
| 端末に保存された下書きだけ（画面のQRは残る） | **この端末から入力を消す** | QR生成後 |

- 「リセット」「新規患者」「入力データを消去する」「破棄」は使いません
- 押した後の表示は「**消しました**」に統一します
- 確認ダイアログには**何が消えて何が残るか**を書き、**2行以内**にします

---

## 8. やらないこと

- `sessionStorage` / Cookie / 外部への通信
- **点数の履歴を端末に残すこと**（共用端末で他患者の記録が見えるため。以前あった「前回との比較」は廃止しました）
- 分析・ログ収集の目的で `localStorage` を使うこと
- フォントの埋め込み（ファイルが数MBに膨らみます）

---

## 9. 出す前のチェックリスト

- [ ] ファイル1つで完結している（外部の読み込みが無い）
- [ ] 機内モードにしても最後まで採点できる
- [ ] スマートフォンの幅（375px）で**横スクロールが出ない**
- [ ] QRが画面幅に収まり、カルテ端末のカメラで読み取れる
- [ ] QRに氏名が入っていない
- [ ] 未回答があるとき、画面とQRの両方に件数が出る
- [ ] 同じ選択肢をもう一度押すと未回答に戻る
- [ ] 下書きが3枠あり、起動時に自動復元しない
- [ ] 消したあとに画面を操作しても、下書きが復活しない
- [ ] 患者氏名・ID などの個人情報が**ファイルの中に入っていない**
